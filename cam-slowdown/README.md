# 카메라 감속 (cam-slowdown)

FSD 주행 중 과속 카메라에 가까워지면 S3XY 커맨더로 **오른쪽 휠 아래**(속도 프로필 낮춤)를 보내고, 지나가면 **휠 위**(평소 프로필)로 되돌리는 안드로이드 앱.

## 동작 원리

```
GPS(1초) ─▶ 앞쪽 카메라 판별 ─▶ 감속거리 안? ─▶ ▼ 클릭 N번 (휠 아래, 감속 프로필까지)
                                   통과+100m ─▶ ▲ 더블클릭 M번 (휠 위, 평소 프로필로) — 끌 수 있음
```

- **FSD v14에서는 휠이 최고속도가 아니라 속도 프로필**(Sloth → Chill → Standard → Hurry → Mad Max)을 바꾼다. Sloth는 제한속도를 지키므로 "내렸다가 평소 프로필로 올리기"가 사실상 속도 조절이다.
- **프로필은 설정에서 고른다.** 평소 프로필(복귀 목표)과 카메라 앞에서 내릴 프로필을 고르면 클릭 수는 그 차이로 정해진다(Hurry→Sloth = 아래 3번, 복귀 위 3번). 내릴 프로필이 Sloth(맨 아래)면 유실 대비 여분 클릭을 더 보낸다(바닥에선 추가 클릭이 무시됨). 복귀는 정확히 내린 만큼만 올린다 — 더 보내면 평소보다 빨라진다.
- **감속 시작 시점도 설정에서 고른다.** 고정 거리(예: 카메라 400 m 앞) 또는 속도별 자동 계산 = (현재속도² − 제한속도²)/(2×감속도) + 속도×반응시간 + 여유. 자동 계산 기본값으로 110→100 카메라면 약 390 m 전. BLE를 켜면 클릭을 다 보내는 시간(4클릭 ≈ 4.6초 ≈ 110 km/h에서 140 m)만큼 더 일찍 시작한다.
- **통과 후 자동 복귀는 끌 수 있다.** 끄면 통과 때 음성만 나오고 휠로 직접 올린다.
- 반대 차로 카메라는 "진행 방향 왼쪽 15 m 밖"이면 감속 후보에서 뺀다(우측통행). 일단 목표로 잡은 카메라는 25 m까지 봐준다(넓은 도로에서 카메라 직전에 "경로 이탈"로 복귀하는 일을 막기 위해).
- 구간단속: 시점에서 내리고, 종점 카메라를 지나거나(길이 데이터보다 우선) 구간 길이만큼 간 뒤 100 m 후 올린다. 시점 바로 옆에 있는 반대 방향 종점은 무시한다.
- 연속 카메라: 통과 직후 다음 카메라가 이미 감속거리 안이면 올리지 않고 이어간다.
- GPS 정확도가 40 m보다 나쁜 fix는 판단에 쓰지 않고, 15초 이상 fix가 없으면 "GPS 신호 없음"을 알린다.

## 설치

1. 폰에서 [최신 빌드 받기](https://github.com/jsbeth-code/yoonmind/releases/tag/cam-slowdown-latest) → `cam-slowdown.apk` 받아 설치 (출처를 알 수 없는 앱 허용 필요).
2. 처음 실행 때 위치·블루투스·알림 권한 허용.
3. **카메라 데이터**: [공공데이터포털에서 '무인교통단속카메라' 검색](https://www.data.go.kr/tcs/dss/selectDataSetList.do?keyword=%EB%AC%B4%EC%9D%B8%EA%B5%90%ED%86%B5%EB%8B%A8%EC%86%8D%EC%B9%B4%EB%A9%94%EB%9D%BC) → 「전국무인교통단속카메라표준데이터」 CSV 다운로드 → 앱에서 **카메라 데이터 불러오기**. 로드 결과에 "구간단속 시점 N" 이 0이 아니어야 정상.

### 카메라 데이터에 대해 (2026-10 수집본 43,764행으로 확인)
- `단속구분`은 숫자 코드: **1 = 속도, 2 = 신호(대부분 신호·과속 겸용), 3 = 버스전용차로, 4 = 불법주정차, 99 = 기타**(`01`, `1+2` 같은 변형 있음). 앱은 제한속도가 적힌 행을 전부 과속 카메라로 보고, 글자로 "신호"만 적힌 행만 뺀다. 신호(2) 카메라는 설정에서 뺄 수 있다.
- `단속구간위치구분`도 숫자 코드: **1 = 시점, 2 = 종점**. 일부 기관은 일반 카메라에도 2를 넣어 두므로, 길이가 타당하거나 "구간"이 명시돼 있거나 같은 노선 25 km 안에 짝이 있을 때만 구간단속으로 본다.
- `과속단속구간길이`는 km(1~23)와 m(1,000~18,637)가 섞여 있고 45·200·99999 같은 쓰레기 값도 있다. 100 미만은 km로 보고, 300 m~30 km 밖이면 "모름"으로 처리한다.
- 방향 정보가 없다(`도로노선방향` 1/2/3은 도로 축 없이는 못 씀). 같은 자리에 차로별로 중복 등록된 행이 2천 개쯤 있지만 무해하다.
- 기관마다 갱신 시점이 달라 일부(대전 2022년 등)는 오래됐다. 고속도로 구간단속만 따로 정확히 쓰려면 [한국도로공사 구간단속현황](https://www.data.go.kr/data/15104214/fileData.do)(노선·방향·시점·종점)이 있지만 이정(km) 기준이라 좌표 변환이 필요하다.

## 단계별 진행

### 1단계 — 안내 전용으로 검증 (차는 건드리지 않음)
- 설정에서 "가상 S3XY 버튼 신호"를 끈 상태(기본)로 **주행 시작**.
- 카메라 앞에서 "과속 카메라, 제한속도 OO. 감속합니다", 지나서 "복귀합니다"가 적절한 타이밍에 나오는지 며칠 확인. 화면에 "감속 신호 시작: Nm 앞"이 지금 속도 기준으로 표시된다.
- 너무 이르거나 늦으면 설정의 고정 거리 또는 감속도·여유거리 조정. 고속도로에서만 쓰려면 "제한속도 미만 무시"를 80으로.

### 2단계 — S3XY 버튼 신호 캡처
버튼이 커맨더로 보내는 블루투스 신호는 공개되어 있지 않아서 직접 기록해야 한다.

1. 차에서 떨어진 곳(커맨더와 연결 안 되게)에서 버튼을 폰에 붙여 둔다.
2. 앱 **버튼 신호 캡처** → 스캔 시작.
3. [클릭 표시] 누르고 버튼 1번 클릭, 몇 초 쉬고 반복 3~5번. [더블 표시] + 더블클릭도 3~5번.
4. **공유**로 결과를 Claude에게 보낸다 → 표시 직후에 바뀌는 패킷을 찾아 BLE 프로필(JSON)을 만들어 준다.

캡처에 아무것도 안 잡히면(버튼이 광고 대신 커맨더와 직접 연결해서 통신하는 방식이면) 스니퍼가 필요하다.
- [nRF Connect (Play 스토어)](https://play.google.com/store/apps/details?id=no.nordicsemi.android.mcp) — 버튼에 직접 연결해 서비스·특성(GATT) 목록 확인
- [nRF Sniffer for Bluetooth LE](https://www.nordicsemi.com/Products/Development-tools/nRF-Sniffer-for-Bluetooth-LE) + [nRF52840 Dongle](https://www.nordicsemi.com/Products/Development-hardware/nRF52840-Dongle)(약 2만 원) + Wireshark — 버튼↔커맨더 통신을 공중에서 기록
- 일반적인 방법론: [Reverse Engineering BLE Devices](https://reverse-engineering-ble-devices.readthedocs.io/)

안드로이드 앱은 광고 주소(MAC)를 바꿀 수 없다. 커맨더가 버튼의 주소로 짝을 지어 두는 방식이면 폰의 광고는 무시될 수 있다 — 그 경우 이 앱은 음성 안내 전용으로 쓴다.

### 3단계 — 커맨더 설정
enhauto 앱에서 새 버튼(폰)을 추가하고, 원글처럼 **클릭 = 오른쪽 휠 아래 / 더블클릭 = 오른쪽 휠 위** 로 지정.

### 4단계 — 연동 (주차 상태에서, 차 프로필 화면을 보면서)
1. 설정에 BLE 프로필 붙여넣기 → "가상 S3XY 버튼 신호" 켜기.
2. **테스트: 감속 신호** → 화면의 프로필이 정확히 설정한 단수만큼 내려가는지 **개수를 센다**(바뀌는지만 보지 말 것). 클릭이 유실돼 덜 내려가면, 복귀 때 평소 프로필을 넘어 올라간다.
3. **테스트: 복귀 신호** → 정확히 평소 프로필로 돌아오는지 확인.
4. 캡처한 click과 doubleClick 페이로드가 **같다면** 커맨더가 타이밍으로 클릭/더블클릭을 가른다는 뜻이다. 그 경우 프로필의 `gapMs`를 1500 이상으로 두고, 클릭 3~4번이 더블클릭(휠 위!)으로 읽히지 않는지 반드시 확인. 앱이 시작 로그에 경고를 띄운다.
5. **가상 주행 테스트** → 음성·BLE 순서가 맞는지 확인. 끝나면 감시가 꺼지므로 실제 주행 전에 **주행 시작**을 다시 누른다.

## 한계·주의
- 카메라 방향 정보가 데이터에 없어서 위치로 추정한다. 중앙분리대 도로에서 반대편 카메라(왼쪽 15~25 m)에 반응할 수 있고, 고가도로·병행도로·급커브에서 오판할 수 있다. 전부 "불필요하게 느려지는" 쪽의 오류다.
- **복귀는 복원이 아니라 설정한 평소 프로필로 올리는 것**이다. 운전자가 주행 중 프로필을 손으로 바꿔 놓았어도 통과 후엔 설정값으로 간다. 그게 싫으면 "자동 복귀"를 끈다.
- 앱은 차 상태를 읽지 못한다(개루프). BLE 클릭이 유실되면 프로필이 어긋난다. 4단계 검증을 거치기 전에는 BLE를 켜지 말 것.
- 지도상 제한속도와 카메라 제한속도가 다르면 Sloth도 지도 기준으로 달린다.
- 앱을 감속 상태에서 정지하거나, 주행 중 CSV를 다시 불러오거나, 시스템이 서비스를 재시작하면 자동 복귀하지 않는다(안전 쪽). 음성으로 알리니 휠로 직접 올릴 것.
- 설정은 주행 시작 때 읽는다. 바꿨으면 정지 후 다시 시작.
- 운전 책임은 운전자에게 있다. FSD(Supervised)는 감독 하에 쓰는 기능이다.

- 빌드: `.github/workflows/cam-slowdown.yml` — `cam-slowdown/` 변경을 푸시하면 테스트 → APK → 위 릴리스에 자동 게시
- 서명 키가 저장소에 있는 디버그 빌드다. 릴리스 키를 GitHub Secrets로 옮기는 게 좋다.

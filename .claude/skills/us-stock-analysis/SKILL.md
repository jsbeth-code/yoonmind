# 미국 주식 종합 분석 (6-전문가 프레임워크)

사용자가 티커(예: DUK, NVDA) 또는 산업명(예: 전력산업, 방산)을 입력하면 아래 순서로 분석한다.
인자에 추가 조건(예: "밸류에이션 과열 제외", "AI 둔화에도 방어되는 종목")이 있으면 스크리닝 필터로 반영한다.

## 권장 모델

- **소유자 기본값(퀄리티 우선): 전 과정 Opus 4.8.** Max 플랜으로 토큰 여유가 있어, 판단의 질이 결과의 질인 이 작업은 수집·해석·판단을 한 모델(Opus)로 통일한다. 밸류에이션 함정 포착(예: KLAC 액면분할, "싼 PER=피크 신호"), 등급 경계 논증, 종목 간 비교 프레임에서 Opus가 확실히 낫다. 속도가 아쉬우면 `/fast`(Opus 그대로 출력만 가속).
- 단, **불필요하게 비싼 토큰은 지양** — 이미 확보한 사실을 재검색/재도출하지 말고, 검색 횟수는 필요한 만큼만(종목당 2~4회 목표). 유료 데이터(시킹알파)가 있으면 중복 검색을 줄인다.
- (참고) 비용 절약이 우선인 상황이면 Sonnet 기본 + 핵심 종목만 Opus 하이브리드도 가능하나, 현재 기본은 Opus 퀄리티 우선. Haiku는 이 멀티스텝 분석에 비권장.
- 이 스킬 자체는 모델을 강제하지 않으며 세션에서 선택된 모델을 그대로 따른다.

## 가독성·친절함 원칙 (일반인+전문가 동시 배려)

보고서는 **주식·산업을 잘 모르는 일반인도 이해할 수 있으면서, 전문가가 봐도 유용**하도록 쓴다. 다음을 반드시 지킨다:
1. **주요 사업 부문은 "쉬운 설명 3종 세트"로**: 각 핵심 사업(예: AWS, 검색광고, HBM)마다 ① **무슨 서비스인가**(초등학생도 알 만한 비유 포함), ② **왜 돈이 되는가**(수익 구조), ③ **유닛 이코노믹스**(고객에게 얼마 받고 얼마 남기나 — 마진·객단가·반복성)를 풀어쓴다.
2. **해자는 "데이터로" 구체화**: "해자가 있다"로 끝내지 말고 **왜 그런지 숫자로**(점유율 %, 전환비용 근거, 마진 격차, 고객 이탈률, 재구매율 등) 설명한다.
3. **낯선 용어는 풀어준다**: 전문용어(예: FCBGA, 인터체인지 수수료, 하이퍼스케일러, HBM)는 쓰되 **처음 등장 시 괄호로 쉬운 뜻**을 붙이고, 보고서 말미 부록에 **"용어 풀이" 표**를 둔다.
4. **회사 연혁(간략 타임라인)**: 창업·상장·주요 전환점·핵심 인수를 3~6줄 타임라인으로.
5. **"최근 몇 년 배경" 섹션**: 최근 3~5년간 ① 산업 변화, ② 재무 변화(매출·이익·마진 추세), ③ 투자자/주주 변화(주요 투자 유치·지분 변동), ④ 경영진 변화(CEO·핵심 임원 교체), ⑤ 관련 시장 변화를 이야기하듯 서술해 "이 회사가 지금 어떤 국면인지" 맥락을 준다.
6. **톤**: 딱딱한 나열보다 "왜 그런지" 이유를 설명하는 친절한 서술. 단 과장·확정적 단정은 피하고 근거를 붙인다.
7. **일반 보고서 양식(불특정 다수 독자 대상)**: 보고서 본문은 특정 개인이 아니라 일반 독자에게 배포되는 문서처럼 쓴다. **"사용자님/사용자 제공/쉬운 설명/주식 처음이어도" 같은 개인화·메타 라벨을 본문에 넣지 말 것.** 친절함은 라벨이 아니라 서술 자체(용어 풀이·유닛 이코노믹스·비유)로 구현한다. 예: 섹션 제목은 "이 회사 한눈에 보기(주식 처음이어도)" ❌ → "기업 개요" ✅ / 표 헤더 "무슨 서비스인가(쉬운 설명)" ❌ → "서비스 내용" ✅ / "사용자님 기준에 부합" ❌ → "밸류·방어·분산 관점에 부합" ✅. 출처에 사용자 제공 자료를 표기할 땐 "HTS 멀티차트(일봉·주봉, 날짜)"처럼 중립적으로 쓴다. (사용자 선호는 판단 근거로 내부적으로만 쓰고, 문서 표면에는 일반화된 투자기준으로 표현.)
8. **말투는 정중하되 부드러운 존댓말(~습니다체)**: 단정적 명령조보다 근거와 함께 안내하는 톤. 어려운 약자·전문용어(EPS, PER, capex, FCF 등)는 본문에서 **처음 등장할 때 괄호로 한 번 더 풀어서** 쓴다(부록 용어표와 별개로 인라인 풀이 병행).
9. **증권사 리포트형 레이아웃 (2026-07-21 도입 — 한화투자증권·하나증권 기업분석 예시 참조)**:
   - **1페이지**: 상단 제목 밴드(회사명·티커·부제·작성일) 아래 **좌측 사이드바 + 우측 본문** 2단. 사이드바에는 ① 투자의견+목표주가 박스 ② Key Data(현재가·시총·52주·주요 배수) ③ **핵심 재무 표 — 최근 실적 2~3개 연도 + 전망 2개 연도의 매출·영업이익·순이익·EPS·PER·ROE를 한 표로** ④ **미니 주가 차트** — 사용자가 붙여넣은 HTS 멀티차트(2×2 구성)에서 **주봉 캔들 패널(우상단, 대략 x 50~100%·y 3~50% 영역)을 PIL로 크롭**해 사이드바 폭에 맞춰 삽입(장기 추세가 보이는 주봉 우선. 크롭 좌표는 이미지 확인 후 미세 조정). 우측 본문에는 핵심 논지 서술.
   - **2페이지: 도표 페이지** — 그 기업에서 중요한 지표(매출 추이·전망, EPS 추이, 부문별 매출 구성, 현금흐름 구조 등)를 [그림N] 캡션의 SVG 차트 2×2로. 차트 규칙: 실적 막대는 진한 네이비(#0d2b4e), 전망 막대는 연한 블루(#8fb8e8)+점선 테두리+"E" 표기(같은 색상 계열의 명암 구분 = 순차 인코딩), **모든 막대에 값 직접 라벨**, YoY는 축 라벨 밑 텍스트로(이중축 금지 — dataviz 스킬 원칙), 각 그림 밑에 자료 출처 표기.
   - **3페이지: 재무제표 종합** — [표1] 실적 추이·전망(수년 실적+전망을 한 표: 매출/YoY/영업이익/이익률/순이익/EPS/PER), [표2] 수익성·재무 상태 요약, [표3] 밸류에이션 표. 컨센서스가 없는 항목을 근사로 채울 땐 반드시 "근사/가정" 각주.
   - 4페이지 이후: 기존 6단계 Part(기업 개요~종합 결론) + 대가 스코어카드 + 부록(기준 설명·용어 풀이) 유지.

## 평가 렌즈 (투자 대가 프레임워크)

6단계 분석을 진행할 때 아래 두 체크리스트를 관통 렌즈로 적용한다. **먼저 종목 성격을 판정**하고 주 렌즈를 고른다:
- **가치·우량주(성숙 캐시카우, 안정적 이익)** → A. 대가 7대 기준을 주 렌즈로.
- **성장·기술주(고성장, 이익 초기/적자, TAM 확장)** → B. 성장주 5대 기준을 주 렌즈로. 단 전통 지표(ROE·FCF·저PER)만 들이대면 NVDA·AMZN·TSLA류를 영영 못 사는 함정에 빠지므로, 미래 지배력·확장성 렌즈를 병행한다.
- 대부분 종목은 둘을 혼합해 본다. 보고서 종합판단(6단계)에서 **핵심 기준별로 통과/미달을 짚고**, 최종 등급이 어느 기준에서 갈렸는지 명시한다.

### A. 가치·우량주 7대 기준 (버핏·멍거·린치·피셔·그레이엄·템플턴·막스)
1. **유망 섹터인가 (전방 성장성)** — 구조적 성장/정책·인구수혜 산업인지. 단 린치식 경계: "모두가 열광하는 핫업종"은 경쟁 격화로 오히려 감점, "지루한 산업의 1등주"나 "정체 산업 속 홀로 고성장 기업"에 가점. 피셔: 수년간 시장평균 이상 매출성장 가능한 초기 구조적 성장 산업 선호.
2. **가격 결정권·경제적 해자** — 버핏: "비용이 올라도 고객 이탈 걱정 없이 즉시 가격 인상 가능한 기업이 최고." 브랜드·전환비용·특허·과점. 멍거: 경쟁자가 막대한 자본을 들고 와도 못 뺏는 **지속가능한** 성벽인지 끊임없이 의심(일시적 우위는 감점).
3. **밸류에이션·안전마진** — PER·PBR·EV/EBITDA·PEG를 업종평균·과거밴드와 비교. 그레이엄/버핏: 내재가치(보수적 DCF) 대비 확실히 싼 구간인지. 단 버핏의 진화: "훌륭한 기업을 적당한 가격에 > 평범한 기업을 싸게" — 무조건 저PER이 아님. 템플턴: **비관론 극대화 시점**(우량주가 일시 악재로 밸류 바닥)이 최고 기회.
4. **재무 건전성·현금흐름(생존력)** — 버핏 '주주이익(Owner Earnings)' = CAPEX 제외 실제 FCF. 현금이 곶감처럼 마르는 기업은 탈락. 린치: 순현금(현금성자산 > 총부채)·이자보상배율 안전 여부 필수.
5. **경영진의 자본배치 능력** — 번 돈을 무리한 확장·엉뚱한 M&A로 날리는가, 아니면 **자사주 매입·소각·배당**으로 주주가치 제고하는가(소각은 희소성↑=주가 엔진). 피셔: 5~10년을 보는 R&D 투자·노사관계.
6. **이익의 질·지속성(예측가능성)** — 막스: 일회성 특수 vs 구독·소모품 재구매 같은 고정 반복매출. 영업이익률(OPM) 15~20%+ 유지·개선 시 이익의 질 우수.
7. **ROE·ROIC(효율성)** — 버핏이 단 하나만 본다면 ROE. **ROE 15%+ 꾸준 유지**를 선호(스노우볼의 핵심). ROIC로 투하자본 효율 교차확인.

### B. 성장·기술주 5대 기준 (피셔·린치·현대 혁신주 투자자)
1. **TAM 크기·침투율** — 목표 유효시장(TAM)이 수십~수백조 규모인가. **침투율 10~20% 미만의 초기 국면(캐즘 통과 직후)일수록 폭발 상승**, 50% 초과 시 성장 프리미엄 꺾임.
2. **성장의 질 (매출성장률·PSR·PEG·PDR)** — 이익 없음은 용서돼도 **매출성장 둔화는 사망선고**. 연 30~50%+ Top-line 성장 확인. 임계점 돌파 시 추가비용 없이 이익이 솟는 **영업레버리지**(SaaS·플랫폼) 구조인지. 이익 미미 시 PER 대신 PSR·PEG·PDR(주가꿈비율) 관점.
3. **네트워크 효과·락인 생태계** — 사용자 증가로 가치가 기하급수 상승하는가(iOS·FSD 데이터·슈퍼차저). 경쟁사가 더 싸거나 좋아도 데이터·익숙함 때문에 못 갈아타는 전환비용 성벽.
4. **R&D 효율·인재 자석** — 피셔: 매출 대비 R&D 비중이 업계 최고 수준이며 그 투자가 적시에 선도 신제품으로 연결되는가. 최고급 인재가 몰려드는 기업인가(인재 몰리는 곳에 파괴적 혁신).
5. **비저너리 창업자** — 창업자가 강력한 지분으로 진두지휘하는가(전문경영인은 단기 실적·주가에 연연해 장기 파괴혁신 회피 경향). 세상의 비웃음을 결과물로 증명하는 무시무시한 실행력(머스크·젠슨 황).

> 적용 원칙: 6단계 각 파트에서 관련 기준을 근거로 인용하고(예: "해자=기준 A-2 통과, 밸류=A-3 미달"), 사용자 기본 선호(합리적 밸류+방어력+테마 비의존)와 충돌 시 그 트레이드오프를 종합판단에서 명시한다.

## 분석 순서 (6단계)

### 1. 섹터 분석가
산업의 과거→현재 구조, 주요 세부 분야와 핵심 기술, 시가총액 상위/유명 기업, **진입장벽이 높은 기술을 가진 기업**(과점 구조 명시), 수요·공급 동인, 장기 전망, 정치·경제·규제 리스크. WebSearch로 최신(현재 연월 기준) 데이터 수집. 산업 전체 요청이면 여기서 유망 기업 목록(테마별 티커 표)까지 만들고, 사용자 조건으로 스크리닝 후 최종 추천 종목을 고른다.

### 2. 뉴스 분석가
최근 6~12개월 + 여전히 주가에 영향을 주는 과거 뉴스. 실적 발표, 계약/수주, 규제·소송, 경영진 변화, 정책(행정명령·FERC 등) 중심. 각 뉴스가 주가에 왜/어떻게 영향을 주는지 해석을 붙인다.

### 3. 기업 분석가
비즈니스 모델과 해자, 기술력, CEO 이력·역량·경영 스타일, 성장 가능성, 밸류에이션(선행 PER, EV/EBITDA, 피어 비교). **유명 애널리스트/기관 의견을 소개하고 비판할 것은 비판**(목표주가 컨센서스, 강세/약세 논거 대비).

### 4. 재무 전문가
최근 분기·연간 실적(매출/EPS/YoY), 가이던스, 대차대조표(부채, FFO/부채 등 신용지표), 현금흐름, 배당(수익률·성향·이력), 자본 조달·자산 매각 등 재무 전략, 장래 전망 예측.

### 5. 기술적 분석가 / 퀀트
MACD, RSI, 하이킨애시, 이동평균(50/200일, 골든/데드크로스), 변동성, 모멘텀, 지지/저항. **매수·매도 타이밍 구간을 구체적 가격대로 제시** (1차/2차 매수, 손절선, 1차/2차 목표가).
- 데이터 수집: 이 환경 프록시는 야후 파이낸스 API·stooq 직접 다운로드를 **차단**함. WebSearch + 공개 기술분석 페이지 요약으로 수치를 수집하고, 소스 간 기준일 불일치 가능성을 보고서에 고지할 것. (WebFetch도 stockanalysis.com/tipranks/trendlyne 등에 403 빈발)

### 6. 종합 판단 전문가
1~5 종합 → 강력매수/매수/보유/매도 결론. 근거, 반대 논거(왜 한 단계 위가 아닌지), 포지셔닝 제안(분할 매수 구간), 시나리오별 대응표(강세/약세/금리 등) 포함.
- **대가 프레임워크 스코어카드 필수**: 종목 성격(가치주/성장주)을 판정하고, 적용한 체크리스트(A 7대 또는 B 5대)의 **각 기준별 통과/미달을 표로** 정리한 뒤, 최종 등급이 어느 기준에서 갈렸는지 한 줄로 요약한다. (예: GE는 A-2 해자 통과했으나 A-3 밸류에서 미달 → 보유.)

### 보고서는 "자기완결적(standalone)"이어야 함 — 제3자 독자 배려
보고서를 읽는 사람이 이 프로젝트의 맥락(대가 프레임워크·스코어카드 약어·투자의견 척도)을 몰라도 이해할 수 있도록, **모든 보고서에 "분석 기준 설명" 섹션을 반드시 포함**한다. 스코어카드에서 "A-3" 같은 약어를 쓰면 그 약어가 무엇인지 같은 문서 안에서 설명돼 있어야 한다. 최소 포함 항목:
1. **분석 방법론**: 6단계(섹터·뉴스·기업·재무·기술적/퀀트·종합판단) 한 줄 설명.
2. **투자의견 척도**: 강력매수 / 매수 / 보유 / 매도의 의미.
3. **대가 프레임워크 설명**: 적용한 체크리스트(A 가치주 7대 또는 B 성장주 5대)의 각 항목이 무엇이고 어느 대가의 관점인지 한 줄씩. (버핏·멍거·린치·피셔·그레이엄·템플턴·막스 / 성장주는 피셔·린치·혁신주 투자자)
4. **면책**: 정보 제공 목적, 투자 권유 아님.
- 위치는 종합판단(스코어카드) 직전 또는 보고서 말미의 "부록"으로. 스코어카드 표의 기준명은 약어가 아닌 **풀이름 + 약어 병기**(예: "A-3 밸류에이션·안전마진")로 쓴다.

## 보고서 생성 (PDF)

0. **작성일은 반드시 실제 오늘 날짜를 쓸 것** — `date +%F` (예: 2026-07-14)로 오늘 날짜를 먼저 가져와서, ① 보고서 본문의 "작성일" 메타줄, ② 파일명, ③ Gmail 제목·본문 날짜, ④ 커밋 메시지에 **모두 동일한 실제 날짜**를 넣는다. 날짜를 하드코딩하지 말 것(과거에 전부 7/8로 잘못 찍힌 전례 있음). 세션이 며칠에 걸쳐 이어져도 각 보고서는 그날의 실제 날짜로 찍혀야 한다.
0-b. **제목 형식(파일명·Gmail 제목 공통)**: `[<티커>]투자분석보고서_<YYYY-MM-DD>_<최종평가>` — 예: `[IOT]투자분석보고서_2026-07-20_HOLD`. 최종평가는 영문 대문자로 `STRONG_BUY`(강력매수) / `BUY`(매수) / `HOLD`(보유) / `SELL`(매도) 중 하나. 즉 제목만 봐도 종목·날짜·최종 투자의견이 드러나야 한다. 파일 저장 경로는 `analysis/reports/[<티커>]투자분석보고서_<YYYY-MM-DD>_<평가>.html`(+`.pdf`). (과거 보고서 파일명은 그대로 두고, 앞으로 작성분부터 이 형식 적용.)
1. `analysis/templates/report_template.html` 을 복사해 내용 채움 (스크래치패드 디렉토리에서 작업)
1-b. **사용자가 채팅에 붙여넣은 차트/이미지를 보고서에 삽입하려면** — 붙여넣은 이미지는 디스크 파일로 저장되지 않지만, 대화 로그(`/root/.claude/projects/<...>/<session>.jsonl`)에 base64로 들어있다. 파이썬으로 그 jsonl을 파싱해 `type=="image"` 블록의 `source.data`(base64)를 디코드→PNG 저장(PIL로 webp→png 변환)한 뒤, 가장 큰/최근 이미지(차트는 대개 2000px 내외 가로형, 내가 만든 PDF 렌더 확인용 PNG는 ~60KB 세로형이라 구분됨)를 골라 `<img src="data:image/png;base64,...">`로 보고서에 인라인 삽입한다. PDF 용량을 위해 가로 1400px로 리사이즈. (검증됨 — GOOGL 보고서에 HTS 차트 삽입 성공.)
2. 한글 폰트 확인: `fc-list | grep -i cjk` 에 Noto CJK 없으면 `apt-get install -y fonts-noto-cjk` (이 환경에서 검증됨. Google Fonts/jsdelivr/GitHub 릴리스 다운로드는 프록시 차단됨)
3. PDF 변환: `analysis/scripts/build_pdf.sh <input.html> <output.pdf>` 사용 (headless chromium)
4. 검증: `apt-get update && apt-get install -y poppler-utils` 후 `pdftoppm -png -r 50` 으로 1~2페이지 렌더링해 한글 깨짐/레이아웃 확인
5. `SendUserFile`로 사용자에게 PDF 전달
6. 완성된 보고서 HTML(+PDF)을 `analysis/reports/[<티커>]투자분석보고서_<YYYY-MM-DD>_<평가>.html` (위 0-b 형식)로 저장소에 커밋 (이력 축적)
